# 从完成的观众技能制作系列短片

打开本仓库后，让 Codex “从已完成模块里选两个题，实录领取包并按陶瓷杯 v2 标准出片”。制作者使用本仓库；观众只领取批次生成的 `ecommerce-automation` ZIP，解压后让自己的智能体读取其中的 `SKILL.md` 和《开始使用》。同一版本的每集指向同一份包。

## 一次准备

本版已在 Python 3.12 验证，建议 Python 3.10–3.12、Node.js 20+、FFmpeg/ffprobe 和 Chromium。从仓库根目录运行以下命令。让 FFmpeg 和 ffprobe 的可执行文件在 PATH 上；Python 和 Node 的 Playwright 都需要能启动各自版本对应的 Chromium。用 `python tools/doctor.py` 检查渲染环境。新配音使用本地 VoxCPM 和自行配置的参考音色。先运行 `python tools/setup_tts.py`，再运行 `python tools/design_voice.py --auto` 生成参考音，或提供已有授权的 `assets/voice/ref.wav` 和 `ref.txt`；独立显卡环境可用 `--voice-python <解释器路径>`。已生成且与文案逐段一致的配音可用 `--voice-cache <缓存目录>`，结构为 `选题ID/voice/`。

```sh
python -m pip install -r requirements.txt
npm ci
python -m playwright install chromium
npx playwright install chromium
```

## 批量运行

```sh
python pipeline/series_batch.py plan --output out/系列 --count 3
python pipeline/series_batch.py run --output out/系列 --count 3
python pipeline/series_batch.py run --output out/系列 --topics B,D
```

`--count` 从已配置且有可运行演示的选题中按登记次序选择下一批。`--topics` 精确指定模块或选题 ID，可用于续跑。只需要采集实录可用 `capture` 替换 `run`。同一输出目录按集复用校验通过的记录；领取包、分镜或实录变更后重新制作。结果保存在：

| 位置 | 用途 |
|---|---|
| `series.json → claims` | 按选题和领取关键词取成片路径、ZIP 路径及 SHA-256 |
| `episodes/.../evidence/execution.webm` | 从点击启动领取包到实际报告或生成素材的连续录像 |
| 同目录 `recording.mp4`、`pack.json`、`runs/` | 入片节选、时段与哈希、运行日志、报告和结果 |
| `episodes/.../film-*/` | 带声音的竖版 MP4、SRT、逐镜检查、运动检查及发布资料 |
| `last-run.json` | 记录本批选择及失败原因，修复后用相同选题续跑 |

录制端先打包、解压并运行这个 ZIP 内的代码和示例。浏览器中的“运行领取包”按钮实际启动模块；录屏保留操作、报告或本次生成的素材。报告视图仅选择和放大原始行列。模组处理用时来自 run.json，和成片剪辑时长分别保存。数据使用包内虚构样例。面向真实店铺时，观众端还需其智能体、浏览器、账号及业务授权。

### 按观众关键词取包

`python pipeline/resolve_claim.py --output out/系列 --keyword 查价` 返回本条成片对应的绝对 ZIP 路径和 SHA-256，供智能体或已有发包渠道直接使用。若同词存在不同版本，附加 `--topic ceramic-price` 精确关联原片。无已完成成片、索引冲突或 ZIP 损坏会明确报错。

## 增加下一集、下一项功能

1. 从成员的选题池 `data/topics.json` 或业务需求选一个具体问题。新能力先在 `audience/ecommerce-automation/` 实现，更新模块注册表、入口、说明、演示输入和版本；已有独立维护的观众包源码可用 `--skill <目录>` 指定。让干净目录里的智能体仅凭领取包完成示例，并核对输出及作用范围。
2. 在 `series/catalog.json` 为选题加稳定 ID、模块、步骤、关键词、两个报告视图和对应的实际结果断言。每一项宣传数字都可回到运行结果。需要新的操作录制方式时同步扩展 `pipeline/series_evidence.py`，保留当次实际运行、原始录像和来源验证。
3. 为选题写分镜、画面、旁白。独立美术目录照 `series/ceramic/` 放 `script.json`、`visual.js` 和本集图片，注册字段 `template` 指向目录名。常规业务题可参照 `series/workflow.js` 新增与该操作匹配的视觉设计。
4. 先 `capture --topics <选题ID>` 核对实际输出，再 `run --topics <选题ID>`。逐镜检查到手资料、实录可读性、动效和字幕，按关键词交付索引中的领取包。现有设置生成本地交付物；平台发布和评论自动发包需另接分发渠道。

## 画面验收

首镜 `hook` 与中段 `mid` 各有一个实录剪辑窗口，均从当次执行的同一原始录像中截取。首镜从第一帧附近开始给出真实操作，再切到实测结果。中段放大连续填写、读回或导出，或逐项核对当前运行的输出。用 `pack.json.steps` 复查原始录像位置，用 `publish.json.recording.slots` 复查成片时段。规模场景与实测结果分开标注。展示「一万件待上架」时，须保留场景示意字样，以及实际演示数量和状态。

参考 `series/ceramic/` 的产品多视角、价签入场、冲突对照、结果归档与品牌收尾。每个内容镜头都需专属 visual，实录窗口能看清操作与结果。正式片须具备实录、运动检查通过、完整音视频可解码，并由制作者查看审片图。原片工程中的可复用画面标准适用于 Codex 与其他制作端。
