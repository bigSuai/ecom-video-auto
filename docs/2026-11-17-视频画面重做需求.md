## 问题

Codex 按现有工作流做出的 `2026-11-17-s7-a`（私域运营）像 PPT：大字靠左、半屏空白、整块淡入淡出、画面长时间不动。原因主要在引擎，不在 Codex：

- 引擎只有 10 种固定场景，agent 只能往 `script.json` 里填文字和选场景类型，画面上限由这些场景代码决定。
- 用同一引擎出的 B 片（2026-11-17-s2-a）也一样。按帧间变化量统计，两条都有约 **31–32% 的时间画面完全静止**。
- 所以"跨 agent 通用"做得过头了：连画面设计也压成了填空，任何模型做出来都一样平。

## 用户的要求

- 写剧本、选题、查重等流程仍然要跨 agent 通用。
- **视频画面按 Opus / Fable 的前端水准来做**：动效要多、要华丽，不能像 PPT。前端是 Opus 的优势，要发挥出来，不为兼容别的模型而降低画面标准。

## 建议方向（新会话先和用户确认再动手）

1. **画面由模型写代码，不只填表。** 每条视频由 agent 写一份专属的动效场景代码（HTML/CSS/Canvas/WebGL），在引擎提供的时间轴、配音对齐、字幕、企鹅、落版、安全区之上自由发挥。固定场景库降为兜底。
2. **动效基础库**：关键帧与缓动、逐字/逐词入场的动态文字、元素错峰入场、镜头推拉摇移、遮罩转场、粒子、数字滚动、图表生长、3D 翻转、持续的微动（呼吸、漂浮、光效），企鹅骨骼式动作而不只是贴图移动。
3. **构图**：竖屏 1080×1920 满屏利用，主体居中偏上，不再大面积留白；信息层次和景深。
4. **质量闸（写进代码和测试）**：
   - 静止检测：任意连续 0.8 秒以上帧间变化低于阈值 → 不出片；整片静止比例目标 < 5%。
   - 抽帧审片：出片前自动出联系表，由 agent 自己看，对照清单（满屏、层次、每 1–2 秒有新的运动）打分，不合格就改。
5. **SKILL.md 分两档**：画面档要求 Opus/Fable 级别的前端模型；其他模型只能用兜底场景库，并在交付时注明"画面为兜底版"。

## 追加：每条视频配一张封面（23:55）

- **只做竖屏一张**：1080×1920（9:16）。抖音、视频号的推荐流都是全屏竖屏，主页九宫格会把封面裁成 3:4 显示，所以标题、企鹅等关键信息放在画面中间的 3:4 安全区内。不做横屏封面。
- **模型**：OpenAI GPT Image 2.5。API 有两个型号：`gpt-image-2.5-flare`（快，官方默认）和 `gpt-image-2.5-sunburst`（细节更好、更慢）。封面每条只出一张，默认用 sunburst，型号做成可配置。Key 从环境变量 `OPENAI_API_KEY` 读取（沿用 `tools/gen_char.py` 的读取顺序），不写进代码、不提交。
- **分工**：画面主体（电商工作场景、氛围、构图）由 GPT Image 生成；**标题文字、企鹅、"韬行科技"标识由代码叠加**，保证字准、品牌固定，不依赖生图模型写中文。
- **规矩**沿用设计文档：不出现真实人物肖像、他人品牌标识，不做假截图；每张记录模型、提示词和生成时间（授权登记）。
- **接入**：`make.py` 出片后自动生成 `out/<编号>/cover.jpg`，路径写进 `publish.json`。和其他检查一样：生图失败不阻断出片，标记"封面待补"。
- **查重**：近 10 条的封面构图和主色不能太像（和视频查重放在一起）。
