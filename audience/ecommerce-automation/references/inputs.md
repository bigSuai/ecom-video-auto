# 输入、来源和指标口径

先由智能体读实际表头和少量样本，结合来源说明确认含义；缺样本时用明确标记的虚构输入测试，不把推测列映射写成业务事实。每行实体身份包含platform、shop_id；货号、订单号和行号使用文本。

## job文件

对象列表可直接放在模块所需表名下。文件输入用以下描述符；mapping方向是“标准字段: 原表列名”，只有显式scales才换算单位：

```json
{
  "data_kind": "user_provided",
  "products": {
    "file": "商品.csv",
    "mapping": {"sku":"货号","name":"品名","spec":"规格","price":"价格分","stock":"库存"},
    "defaults": {"platform":"用户平台","shop_id":"当前店铺","currency":"CNY"},
    "scales": {"price":"0.01"}
  }
}
```

file相对路径以job.json所在目录为根。标准输入支持CSV（UTF-8/BOM或GB18030）、JSON对象列表、XLSX（需openpyxl，sheet可指定可见表）。单文件10MB、10000行、100列；XLSX公式须核对后粘贴为确定值，不能把缓存结果当已核实事实。旧xls先由用户或宿主工具转换；不要修改唯一原件。

公共层保留source_file/source_row/source_hash/data_kind、原行_raw及映射审计；Excel数字型编码发出待核对提示，不能恢复已丢前导零。CSV导出对危险公式前缀加单引号；JSON中的业务值不因此改写。HTML预览最多1000行，完整结果见CSV/JSON。

## 统一口径

- 同名字段可能含义不同。区分支付金额、结算实收、标价/券后价、退款发生日、成交日、广告归因收入与店铺总收入。
- 每次映射记录原列、金额单位、币种、时区、日期和广告归因窗口。不能只重命名字段就声称已统一。
- 多币种分别汇总，不自动换汇。比例按合计分子/合计分母重算；0分母和缺失不填0。
- 来源已扣费用不可重复扣；未知成本费用不当零。贡献收益不称净利润，统计相关性不写成已证实原因。
- 未验证的口径用不同metric_basis/归因组保留，不相加。D订单日期要求先转换为统一业务日，金额paid_amount为优惠后、未再扣输入费用的支付事实。

如用户已用成员商品检查器，读取其“整理结果”表并按表头映射：商品名称→name、SKU编码→sku、规格→spec、售价→price、库存→stock；平台/店铺/币种按确认的上下文补。无需安装成员工具即可使用本包。
