# 浏览器连接、观察与中断恢复

本包不启动真实商家操作，也不绑定某一浏览器服务。Agent 执行浏览器流程时，优先使用宿主已提供、能力足够的浏览器工具；Kimi Browser Extension + WebBridge 是可选适配路线。仅加载本 Skill、选择某个模型或打开普通聊天网页，不会自动获得浏览器控制能力。

## 先检查实际能力

在当前宿主发现可用工具并读取其当前说明，核对是否具备：列出/选择目标标签、读取快照/文本、填写和选择、上传本地文件、点击、等待页面条件、读回字段及截图/下载。没有某项能力时，给出实际缺项和可用替代；不要声称已连接，也不虚构工具名。调用时使用实际工具说明支持的参数。

原生宿主路线按这些检查点执行：

1. 查看当前启用浏览器与标签；用户指定浏览器/标签时遵从。确认所选页面为本任务对应的店铺和阶段，只读取协作需要的信息。
2. 建立本任务独立的会话/任务标记，保持整个任务复用；独立并行任务使用不同标记。借用用户现有标签，不关闭或随意导航走它；需要并存页面时另开任务页。
3. 用当前快照确定当前字段、行和按钮。页面变化、导航、弹窗或元素失效后重新观察；只按当次观察到的元素引用操作，不把真实后台选择器、坐标或商品 ID 写死在可移植包中。
4. 填写后等待可观察结果，读回表单值、选项、SKU 映射和保存提示。截图需要打开查看后才能作视觉判断。工具返回“已派发/成功”只证明调用结果，不能替代页面证据。

## 可选 Kimi 路线

公开入口：[Kimi 浏览器扩展](https://www.kimi.com/products/kimi-browser-extension)、[官方帮助](https://www.kimi.com/products/kimi-webbridge)。扩展、桥接二进制和 Agent 指令是不同组件。浏览器侧安装确认、登录及验证码由用户处理；不要要求向聊天粘贴 Cookie、密码或桥接秘密，也不自动执行网上安装脚本。

默认二进制位置：Windows 为当前用户的 `%USERPROFILE%\.kimi-webbridge\bin\kimi-webbridge.exe`；macOS/Linux 为 `~/.kimi-webbridge/bin/kimi-webbridge`。这是可选适配器的常见安装位置，用户改过位置时核对实际路径。本包不要求作者的账号或固定本机路径。

1. 检查二进制是否存在，执行其 `status`。没有二进制时说明缺桥接组件并给官方入口；不要把端口响应误认成已安装。
2. 已安装但未运行时执行 `start`，再查状态。服务地址取 `status` 的实际 `addr`、运行中的 `port` 或 `start` 输出；`127.0.0.1:10086` 只是默认示例。返回非预期网页或非 `ok` 响应信封时，应确认实际地址和端口占用。
3. `extension_connected:false` 或 `extension_not_connected` 表示浏览器侧尚未接通。给用户当前实际 WebSocket 地址（例如实际监听 `127.0.0.1:10086` 对应 `ws://127.0.0.1:10086/ws`），请用户在所选 Chrome/Edge 的 Kimi 扩展设置中按当前界面完成“本地 Agent 远程控制”连接。仅打开侧栏或能聊天不算接通。状态恢复后再读取页面。
4. 每个命令 POST 到实际地址的 `/command`，检查 HTTP 结果及响应信封：`{"ok":true,"data":...}` 或 `{"ok":false,"error":{"code":"...","message":"..."}}`。HTTP 200 本身不代表动作成功。
5. 使用本任务生成的唯一顶层 `session`，例如 `ecommerce-<随机任务ID>`，全任务复用。先 `list_browser_tabs`，按 URL、标题和实际店铺身份定位目标，再用 `attach_tab` 的明确 `tabId` 借用页面。需要新页时 `navigate` 并设置 `newTab:true`，首次可加用户语言的 `group_title`。同域多个页面不用仅按域名查找代替精确标签选择。

请求形状如下；具体动作先核对当前适配器说明：

```json
{"action":"list_browser_tabs","args":{},"session":"ecommerce-unique-task-id"}
```

Windows 请求体每次由宿主文件写入工具保存到唯一 UTF-8 JSON 临时文件，再用 `curl.exe --data-binary @实际文件路径` 发送，完成后普通删除该请求文件。不要使用裸 `curl` 别名、`echo`、PowerShell 管道或命令行内嵌中文 JSON。macOS/Linux 使用正确引用的请求体；有转义问题也改用独立文件，不原样重复失败命令。端口、URL和文件路径来自已核对的实际值，不把用户输入拼成 shell 代码。

| 动作 | 适配参数和验收 |
| --- | --- |
| `snapshot` | 可用 `format:"aria"`、`max_chars`；使用当次元素引用，截断时按返回游标续读 |
| `find` / `read_page` | 先定位再缩小读取；按 `complete`、`nextStart` 和提示继续，不能把不完整页面当作无内容 |
| `fill` / `click` | 使用已观察的 `selector`；文本优先 `fill`，编辑已有字段前读其当前值 |
| `mouse_click` / `send_keys` | 需要真实输入时先聚焦并核对实际焦点，再发送按键；背景页按实际支持使用 `focus_emulation` |
| `evaluate` | 只读核对当前值、选中项、SKU行和 `document.activeElement`；不调用隐藏发布接口或绕过页面限制 |
| `upload` | `selector` 与本次选择的绝对文件路径数组；等待缩略图/成功提示，核对张数、顺序和主图 |
| `wait` | 使用已观察的文本、选择器或 frame 条件；超时后重新快照，不把固定等待时间当完成证明 |
| `screenshot` | 查看返回的本地截图后判断；证据文件使用唯一文件名 |
| `list_tabs` | 记录本任务当前标签、`tabId` 和 `borrowed`，恢复时精确选回 |

需要键盘输入时，先通过真实点击聚焦，再只读确认 `document.activeElement` 是具体目标；SKU表必须对应正确行及字段。`click` 成功并不保证焦点正确，不能直接发 `Mod+A`、删除或 Enter。工具不支持核对焦点时，改用可靠的填写能力或等待用户处理，不盲发快捷键。

主页面可能只是 iframe 容器。依据快照实际返回的 frame 句柄读取嵌入文档，并检查响应确实对应 frame；顶层元素引用不能假定跨 frame 操作。当前工具不支持嵌入内容操作时说明具体缺项，选择受支持路线。

## 上传、下载和恢复

- 上传失败：保留实际错误，核对扩展连接、文件存在性、格式、大小和页面限制。只有实际报错或官方说明要求时，指导用户在 Chrome/Edge 扩展详情中检查“允许访问文件网址 / Allow access to file URLs”；不要把所有上传失败归于权限，也不开启无关权限。重试后仍须检查实际缩略图和提示。
- 下载报表：通过当前页面的下载控件取得文件，等待宿主下载回执或文件落盘；核对本次文件的路径、名称、大小、表头、日期、店铺范围和行数。点击“下载”不证明文件已经可用，不能用另造 CSV 冒充下载结果。
- 未提交前断线：保存已核验字段与草稿 ID，重连后先读页面和身份，再从有效检查点继续。页面内容与旧记录不符时重新核验。
- 已发出提交但结果不明：先按实际 ID 或平台/店铺/SKU 查询已有结果，唯一匹配后记录；不直接重复点击提交。无法唯一匹配时暂停相关项并说明歧义。
- 登录、验证码或人机验证：暂停依赖步骤，由用户完成，观察恢复后继续。不要请求验证码交给 Agent 或规避验证。
- 服务已运行但扩展未连接：不要反复 start 或自动重启。`stop`、`restart`、`upgrade`、`uninstall`、端口调整不作为默认修复。版本提示不阻碍当前操作时保留提示，确实要求更新时保存检查点并给官方步骤。

等待登录、用户核对、未提交草稿或其他工作仍在进行时保留会话和页面。真正完成且结果已保存后，可用 Kimi 的 `close_session` 清理本任务自建临时页，借用页保留；页面仍是交付内容或有未保存工作时保留。其他宿主同样按标签所有权与当前任务需要处理，不关闭用户原有标签。

## 本地演示验收

仓库测试目录中的 `browser_fixture.py` 仅供开发验收，不是安装包运行依赖。开发者启动它时使用 `--port 0`，从 stdout 首行 JSON 读取实际 loopback URL；也可指定 `--ready-file` 保存就绪信息。夹具只监听 `127.0.0.1`，页面始终标记虚构数据。

演示页面有商品选择器、五个字段、每字段状态、全部核验、保存演示草稿及“核对并确认提交”按钮。真实浏览器 smoke 应填写两款商品，读回并记录字段，停在确认提交边界，再用本机 `/mock/events` 确认没有提交事件。活动页展示虚构活动及规则，报表页提供实际本地 CSV 下载；验证下载落盘后再检查内容。该演示只证明当前适配路线可操作本地页面，不能当作真实平台已填报或上架的验收。
