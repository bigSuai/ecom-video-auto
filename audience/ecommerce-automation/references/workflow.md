# 整链执行与资料衔接

整链目标不是机械跑七遍命令。按用户当前经营阶段选择顺序，在同一任务目录保存task.json，记录目标、平台店铺、资料路径、当前模块、已完成产物、具体授权范围、待补项和下一步。不要写密码、Cookie或供应商密钥；工具连接沿用宿主。

1. **G选品**：整理行业和单品，确认同款、成本与可售条件，给候选与价格提醒。用户确定本轮商品后继续。
2. **B资料**：统一格式并检查。读取tables.normalized和issues；只把用户/来源已确认的修正填入新输入，不用检查器猜价格库存。通过的行进入下游，有问题的保留阻塞。
3. **E素材**：以确认商品事实和合法来源素材生成初稿；让用户挑选/重做，交付已选包。素材清单记录商品身份，供A引用，不混不同款。
4. **A上架**：把name明确映射为title；补当前平台类目、属性、品牌凭证、图片、SKU和物流承诺。按队列逐款填报、读回，确认后按授权提交并查询状态。
5. **C推广**：收集当前平台活动和截止时间，对齐关键词/投放数据后形成清单、测算、提醒。报名或消费不由此模块自动执行。
6. **F售后**：通过已有授权ERP工具或页面/导出读取订单库存和消息，关联售后待办。仅生成清单与草稿；消息发送证据与本地处理分开。
7. **D复盘，G持续监测**：按统一业务日取得报表并对账；D给事实和待核对结论，G给价格变化提醒。用户改变商品/活动方案后回到对应环节，不自动改价。

不同阶段的数据不可凭空产生：B的售价库存不是订单/成本/广告事实，A已提交不是在售，F草稿不是已回复，G行情不是销量预测。能独立做的环节先完成，缺项只阻塞相关动作。

## 计时和进度

包内run.json记录处理及文件输出耗时。浏览器取数、填报或生成服务的完整耗时由宿主从第一项操作到最终可观察结果计时，保存输入数、成功数、失败数、待确认数及实际时间，注明是否包括人工等待。字段读回、来源页面与导出文件作为证据，测试用时不能代替业务流程实测。可用 `session-start/session-finish` 辅助在同一电脑记录端到端耗时。

中断时保存task.json与模块自己的queue/manifest/state。恢复先读最新输入与平台现状，核对是否已有草稿、重复记录或已完成生成。原用户标签保留；不要用一次断线重开整套任务。

同一电脑计时示例：`python scripts/ecommerce.py session-start --output 任务/session.json --label 浏览器填报`；实际操作完成后执行 `session-finish --session 任务/session.json --processed 实际数量 --evidence 证据文件路径`。包含实际等待，不能跨机器继续；业务数量仍由证据核对，不把手填数量当自动核验。
